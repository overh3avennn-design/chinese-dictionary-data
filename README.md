# chinese-dictionary-data

Данные китайско-русского словаря **大БКРС** для страницы «Словарь» сайта
[chinese-learning-platform](https://overh3avennn-design.github.io/chinese-learning-platform/dictionary/).
Репозиторий отдельный, чтобы основной оставался лёгким; данные отдаёт его
собственный GitHub Pages:
`https://overh3avennn-design.github.io/chinese-dictionary-data/`.

Источник — ежедневная база БКРС со страницы <https://dabkrs.com/p47>
(формат DSL). «Базы можно использовать свободно в любых целях. Можно указать
данный сайт как источник» — на странице словаря стоит ссылка на
[bkrs.info](https://bkrs.info).

## Обновить словарь

```sh
python3 -I build/build.py --download      # скачать свежий dabkrs_*.gz в source/ и собрать
git add -A && git commit -m "Словарь vГГММДД" && git push
```

Сборка занимает 6–7 минут и около 2,5 ГБ памяти. Каждая сборка пишет новую
папку `v<версия>/` и удаляет прежнюю, `meta.json` переписывается последним.
Страница, у которой в кэше остался старый `meta.json`, получит 404 на файл
удалённой версии, перечитает `meta.json` и повторит поиск.

Каждое обновление добавляет в историю git ещё ~170 МБ (в сжатом виде).
Если история станет мешать, её можно сбросить: собрать, сделать одну
коммит-сироту (`git checkout --orphan`) и запушить с `--force`.

`build/build.py --report-only` — только показать размер уже собранного.
`build/hsk-words.txt` — слова HSK 2.0 и 3.0 (уровни 1–6): их статьи идут
первыми в результатах.

## Устройство

```
meta.json             версия, число статей, каталоги файлов
v<версия>/e/N.json    статьи
v<версия>/zh/N.json   индекс иероглифов
v<версия>/py/N.json   индекс пиньиня
v<версия>/ru/N.json   индекс русских слов
```

**Номер статьи (ID)** — её место по важности: сначала слова HSK по уровню,
потом остальные по оценке употребительности (сколько основных статей
содержат слово, как часто оно встречается в примерах, длина статьи, есть ли
пиньинь и русский перевод). Поэтому все списки ниже возрастают, а внутри
группы результаты идут по ID.

**Статьи** — `e/N.json`, массив `[иероглифы, пиньинь, перевод]` по порядку ID,
файлы до 32 КБ. Где кончается каждый файл, сказано в `meta.json` → `e`
(номера первых статей следующих файлов, сжатые как списки ниже). Перевод —
строки значений через `\n`; из тегов DSL оставлены только `[p]…[/p]`
(пометки: гл., см., уст.) и `[i]…[/i]` (комментарии курсивом), остальные
убраны, их текст сохранён. Пиньиня нет у 2,6 млн статей — в основном это
отраслевые термины.

Файлы мелкие, потому что результаты одного запроса разбросаны по всему
словарю и на каждый грузится целый файл: первые 10 результатов — около
120 КБ в gzip, а с файлами по 256 КБ было бы ~900 КБ.

**Индексы** — `zh/`, `py/`, `ru/`, файлы около 48 КБ. Файл — массив строк
`«<общее начало с предыдущим ключом: цифра 0–9><остаток ключа>|список|список…»`,
ключи отсортированы как строки JavaScript (по кодовым единицам UTF-16).
`meta.json` → `zh`, `py`, `ru` — первые ключи файлов: нужный файл находится
двоичным поиском. Список — возрастающие ID: первый и разности, каждое
число группами по 5 бит (младшие вперёд) символами
`A–Z a–z 0–9 - _`, значение ≥ 32 — «дальше ещё».

| индекс | ключ | списки |
|---|---|---|
| `zh` | заголовок | ID статьи · до 100 самых важных статей, в заголовке которых он есть (学 → 大学, 学习…) |
| `py` | пиньинь с цифрами тонов: `shui3guo3`, ü → `v`, лёгкий тон без цифры | статьи, где это первое чтение · где не первое · до 100 статей, чей пиньинь без тонов начинается так же (только у первой записи слога) |
| `ru` | русское слово, строчными, ё → е | где оно главное значение (первая строка перевода) · где одно из других значений · где просто встречается |

Записи `py` отсортированы по пиньиню без тонов, так что все тона слога
(`shi`, `shi1` … `shi4`) стоят подряд и в одном файле; в `meta.json` → `py`
лежат ключи без тонов. Служебные русские слова (и, в, на…) в третий список
`ru` не попадают.

Как страница ищет: иероглифы — точный заголовок, затем слова, в которые он
входит; пиньинь — с тонами (`shuǐ`, `shui3`) или без, сначала точное
совпадение, затем слова, которые с него начинаются; русское слово — сначала
статьи, где оно значение, затем где встречается, затем другие формы
(дом → дома, домашний). Код — `js/dictionary.js` основного сайта.
